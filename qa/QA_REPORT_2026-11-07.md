- 점검일: 2026-11-07
- 대상: https://devopen-gpu.jntp-ax.or.kr/i/GSCmyWGuBKr2fXRa/ (Streamlit 1.67, 실제 검사 API 연결 상태, guest 로그인)
- 방법: Chrome(Claude in Chrome)에서 직접 조작. 창 크기는 모니터 제약으로 줄어들지 않아, **같은 출처 iframe을 정확한 뷰포트 크기로 띄워** 7개 크기 × 11개 페이지를 측정함(가로 스크롤, 화면 밖으로 넘친 요소, 44px 미만 터치 대상, alt 누락, 페이지 예외). devicePixelRatio는 2로 고정.

## 3. 바로 고칠 수 있는 상위 5개

### #1 후보 없음 → "결함 미검출" (치명)

```diff
--- inspection.py
@@ def model_view(mode, body):
-    return {'label': label, 'score': top['score'] if top else None, 'defect': bool(bad)}
+    return {'label': label, 'score': top['score'] if top else None, 'defect': bool(bad), 'none': top is None}
@@
 def verdict(defect):
     return '불량' if defect else '양품'
+
+
+def verdict_of(view):
+    """Model verdict as shown on screen: no candidate above the threshold is not the same as 양품."""
+    return '결함 미검출' if view.get('none') else verdict(view['defect'])
```
화면에서 `verdict(v["defect"])` / `ins.verdict(view["defect"])`를 쓰는 곳(직접 판단 실습 결과 카드, AI 판정 검토 "AI 제안", 오답 복습)을 `verdict_of(v)`로 바꾸고, 색상 클래스는 `good`/`bad` 대신 중립(`none`)을 쓴다. 채점(맞음/틀림) 로직은 바꾸지 않는다.

## 4. 통과한 항목

- **가로 스크롤 없음**: 360·390·768·1024·1440·1920·2560 × 11개 페이지(홈, 분류/탐지/분할 실습, AI 판정 검토, 가이드, 판정 클래스, 마이페이지, 검토 기록, 개인정보 안내, 로그인) 모두 `scrollWidth == 뷰포트 폭`. 화면 밖으로 넘친 요소 0개.
- **페이지 예외 없음**: 77개 조합 모두 `stException` 0개. 콘솔 오류 0, 4xx/5xx 리소스 0.
- **최대 폭 제한**: 2560px에서 본문 1216px 가운데 정렬.
- **세로 쌓임 순서**: 모바일에서 검사 제목 → 사진 선택 → 결과 → 버튼 순서로 작업 흐름과 일치.
- **긴 파일명**: 80자 한글·영문 혼합 파일명이 말줄임표로 처리되고 겹치지 않음.
- **세로로 긴 사진(600×2400)**: 비율을 유지한 채 표시.
- **손상된 이미지**: "사진을 읽을 수 없습니다. 정상적인 JPEG/PNG 파일을 선택해 주세요." + "이 사진 건너뛰기" 버튼.
- **오류 메시지(코드 확인)**: 타임아웃(최대 300초), 연결 실패, JSON 아님, 429 재시도 시간, 해상도 초과(2천만 화소), 10MiB 초과 모두 한국어 안내.
- **진행 상태**: "0 / 2장 검토", 썸네일 대기열로 몇 번째인지 표시.
- **클릭 업로드**: "끌어다 놓거나 클릭해 추가" 지원.
- **결과 카드**: 맞음/틀림이 색(하늘/빨강)뿐 아니라 "맞음/틀림" 글자 배지로도 구분.
- **오답 복습(1158×718)**: 대화상자 안 스크롤 없음, Esc로 닫힘.
- **챗봇(360px)**: 패널이 화면 폭 360px에 맞고, 대화 영역 `aria-live="polite"`, 답변은 DOM 노드로 그려 XSS 위험 없음.
- **포커스 표시**: 탭 버튼에 3px 파란 외곽선, `:focus-visible` 규칙 26개.
- **innerHTML**: 사용 3곳 모두 고정 문자열(데모 계정 안내, 전송/중지 아이콘). 파일명·사용자 이름은 `html.escape` 처리(29곳).
- **테스트**: `python -m unittest discover -s tests` 36개 통과. (`pytest`는 미설치)
- **오버레이 정렬**: 박스·마스크를 서버에서 사진에 직접 그려 하나의 이미지로 보내므로, 창 크기·회전·DPR이 바뀌어도 어긋날 수 없는 구조(구조 확인. 박스가 실제로 그려진 사례는 이번에 관찰하지 못함).

## 부록 · 확장성 (E)

새 검사 목적을 추가할 때 고쳐야 할 파일:

1. `inspection.py` — `MODES` (번호, 제목, 모델, 클래스 목록)
2. `assets/site.js` — `modes` 표시 이름 (중복 정의)
3. `home.py` — `SLIDES`, `illustration()` 그림
4. `ui.py` — `MENU` (검사 실습·판정 클래스 메뉴)
5. `classes_page.py`, `guide_page.py` — 안내 문구
6. `review.py` — 검토용 클래스 선택지 (`correction_choices`)

- 판정 로직(`model_view`, `verdict`, `is_defect_class`)은 화면 코드와 같은 `inspection.py`에 있다. `judge.py`처럼 분리하면 테스트와 재사용이 쉽다.
- 표시 기준 점수는 `SHOW_SCORE` 상수 하나로 관리된다(`thresholds.json` 없음).
- CSS 변수 토큰은 있으나(`var(--` 298회) 직접 쓴 색 코드도 178개 남아 있다.
- 화면 문구가 Python·JS 곳곳에 한국어로 직접 들어 있어 영문 UI 추가는 어렵다.
- 검토 기록은 `accounts.py`의 SQLite 함수(`add_review`, `reviews_for`)로만 읽고 쓰므로 다른 DB로 옮기기 쉽다.
